# Исследование: что действительно переиспользовать

Подробные первоисточники Sxx — в [SOURCES.md](SOURCES.md). Выводы ниже — синтез для **одного организатора на поездку**, не рейтинг всех туристических продуктов. Туристическое исследование версии 0.1 сохранено; в 0.2 изменён рекомендуемый способ исполнения — облачный чат в первую очередь. Ни демо, ни интеграции не разворачивались; не доказаны региональная доступность и live-покрытие.

## 1. Три архитектурных пути

| Подход | Что выиграем | Что потеряем | Решение |
|---|---|---|---|
| Готовый planner + внешний LLM | Быстро получаем карту, дни, расходы, совместный доступ | Своё исследование, доказательства/скоринг и бренд придётся жить отдельно | Хорошая альтернатива при приоритете организации уже выбранной поездки |
| Cloud-first travel desk + необязательная локальная оболочка | Один метод, переносимый результат, сильная модель без требований Git/субагентов к путешественнику | Нужно доказать доступ к данным, смысловой handoff и экспорт в конкретной среде | **Рекомендовано в 0.2** |
| Собственный агрегатор/booking platform | Контроль покупки и полный пользовательский путь | Контракты, платежи, возвраты, поддержка, парсеры, uptime | Не соответствует pet-цели |

Форк готового приложения полезен, когда его целевой сценарий уже ваш. Иначе экономия на первых экранах превращается в поддержку чужой архитектуры и вечную синхронизацию upstream.

## 2. Кандидаты для переиспользования

Stars — округлённый срез на 29.09.2026. «Взять» означает применить после минимальной проверки выбранной версии, не слепо установить последнюю.

| Модуль/проект | Stars / лицензия | Что взять | Чего не делать |
|---|---|---|---|
| Pydantic [S27] | ~29k / MIT | Валидируемые модели и ошибки полей | Не пытаться выразить человеческий вкус сотнями hard gates |
| Jinja [S26] | ~11.8k / BSD-3-Clause | Один источник данных → MD/HTML views | При отсутствии шаблонизатора рендерить из принятого содержания и сверять, не генерировать новые цифры |
| Trafilatura [S30] | ~6.9k / Apache-2.0 | Извлечение основного текста разрешённых страниц | Не путать удаление boilerplate с устранением рекламной предвзятости |
| Playwright MCP / CLI [S31] | ~37.7k / Apache-2.0 | Точечная проверка сложной страницы, UI-smoke | Не превращать каждый search в долгую браузерную сессию |
| dzhng/deep-research [S33] | ~19.7k / MIT | Ограничение ширины/глубины, итеративные вопросы | Не форкать весь набор API-зависимостей ради пяти маршрутов |
| Crawl4AI [S32] | ~84k / Apache-2.0, проверить NOTICE | Резерв для повторяющейся проблемы сложного чтения | Не держать три конкурирующие crawling-системы без необходимости |
| TREK [S07] | ~14.4k / AGPL-3.0 | Паттерны дни/карта/расходы, возможный будущий экспорт | Не переносить весь auth/plugin/offline-sync стек в выходной прототип |
| AdventureLog [S08] | ~3.8k / GPL-3.0 | Паттерны планирования и истории поездок | Не начинать с travel social network |
| awesome-digital-nomads [S20] | ~1.1k / waiver в README | Категории и начальный словарь источников | Не считать все вложенные ссылки свежими |
| shadcn/ui [S45] | ~125k / лицензию проверить на pin | Компоненты, если React уже осознанно выбран | Не вводить React только ради популярности набора |

Основная рекомендация 0.2: **самостоятельный протокол + сильная модель в обычном чате + доступный разрешённый поиск + переносимая книжка**. Pydantic/Jinja/FastAPI и один harness остаются рекомендацией **только для локального усиления**; путешественник ничего не устанавливает. Браузер/извлечение/плагины подключаются по доказанной потребности, не списком требований. [S25–S28, S46–S50]

## 3. Travel API и MCP: что реально означают обещания

| Канал | Роль | Ограничение, которое нельзя спрятать |
|---|---|---|
| Aviasales Data API [S01] | Где искать дешёвое направление/окно | Кэш, не live inventory |
| Aviasales live search [S40] | Потенциальный поиск конкретных вариантов | Другой доступ/условия, не автоматически вместе с Data API |
| Booking.com Demand [S02] | Размещение/предложения при партнёрском доступе | Контракт и onboarding |
| Яндекс Путешествия API [S03] | Кандидат РФ-размещения | Доступ запрашивается; приложение/трафик сверять с условиями |
| Ostrovok API [S05] | Партнёрский канал размещения | Интеграционные требования; не нужен booking lifecycle в V0 |
| Duffel [S04] | Конкретные flight offers | Срок действия, покрытие перевозчиков и access отдельно |
| Skiplagged MCP [S34] | Официально описанный поисковый endpoint | Не тестировался; исключать hidden-city, проверять покрытие/условия |
| Expedia / Skyscanner / Booking.com / Tripadvisor apps | Удобны в поддерживающем host | ChatGPT connection не равна переносимой интеграции для repo-приложения |
| Обычная страница перевозчика/отеля | Узкая проверка условий и предложения | Автоматизация может быть ограничена, сессия/цена меняются |

**Кандидаты не для ядра и в этом атоме не включены.** fast-flights/AWeirdDev — неофициальный scraper, не устанавливать. trvl — единый интерфейс, но лицензия PolyForm Noncommercial, не включать. TREK и AdventureLog — паттерны органайзера, не источник наличия. Skiplagged MCP не является core route. Amadeus Self-Service не включать. LetsFG в текущем реестре исследования не разобран и не устанавливается. Ни один из них не форкается и не получает платёжные права. [S35–S38, S06, S07, S08, S34]

Возможность получить успешный ответ от API не равна праву сохранять/переиздавать данные. Перед enable фиксируются: доступ, условия использования, модель тарификации, лимиты, необходимые права, test query, дата и fallback. Версии pin в реализации, не вечные номера в blueprint.

## 4. Почему подобные идеи застревают

Это **карта рисков**, а не статистически доказанный список причин закрытия стартапов. Она опирается на ограничения поставщиков, первичные работы и конкретный самоотчёт solo-разработчика. Утверждать «все бросают по этой причине» оснований нет.

| Боль | Почему возникает | Минимальный ответ |
|---|---|---|
| Рекламный суп вместо открытий | Поиск рейтингов и пересказ статей не дают иной информации | Поиск experience-гипотез, локальные авторы, контрсвидетельства |
| Цена красивая, купить нельзя | Кэш, другой состав, скрытые условия | Evidence scope и recheck на полный состав |
| Хорошая точка в неверном месте | Идентификация по названию без географии | Проверять координаты/город/доезд, а не только существование |
| Дни по отдельности хороши, поездка не работает | Раздельная генерация теряет общие даты, бюджет и переезды | Общий brief, один timeline, сквозной критик |
| Поправка пользователя ломает остальное | Нет версии ограничений и зависимостей | REFINE с явной дельтой и минимальным пересчётом |
| Браузер/субтитры постоянно отваливаются | Нестабильные неофициальные каналы и правила доступа | Fallback и ограниченный retry; не собирать proxy-операционку |
| Исследование неожиданно дорого | Поля API, повторные place lookups, много полнотекстных циклов | Usage ledger, кэш допустимых стабильных данных, narrow field masks |
| Красивый интерфейс создаёт лишнее доверие | Человек видит уверенный текст, а не качество проверок | Фактические статусы отдельно от медальки |
| Путеводитель слишком длинный | Система оптимизирует объём, а не действие | Первый экран — решение, дальше progressive disclosure |
| Отпуск превратился в административный проект | План оптимизирует деньги, игнорируя усилия | Effort budget и готовые пакеты как нормальный baseline |
| Обслуживание дороже пользы | Слишком много интеграций, автозапусков и источников | Один primary + один fallback по функции, on-use refresh |
| «Полная безопасность» существует только в prompt | Инструменты/страницы имеют лишние права | Реальные host restrictions и read-only маршрут |

В авторском кейсе Roam описана неприятная граница: объект существовал в базе places, но был в неверной географии; некоторые участники всё равно высоко оценивали план. Автор также описывает затраты API и переработку после пользовательского тестирования. Это самоотчёт небольшой выборки, не независимый benchmark, но полезное предостережение: perceived trust и фактическая точность — не одно и то же. [S39]

## 5. Что брать у премиальных сервисов

Black Tomato — внимание к желаемому переживанию, личным особенностям и передаче поездки в исполнение. Не «дорогое место в красивой обложке», а согласованная композиция отдыха. ЕНОТ может перенять этот принцип, но не обещать их человеческие контакты, закрытые возможности и круглосуточный сервис. [S11]

Wanderlog — собрать карту, план и бытовую информацию рядом; Mindtrip — связывать вдохновение с реальными местами. Собственный differentiator не «тоже AI», а объяснимая сравнительная работа и аккуратная передача в действия. [S09–S10]

Вне туризма берём два проектных приёма: из editorial publishing — один semantic content pack и контролируемые views; из операционных runbook — ближайшее действие, условия, резервный путь и контакты. Это наши проектные аналогии, не утверждения об эксклюзивной методологии какого-либо бренда.

## 6. Предел проведённого исследования

Нет live-обкатки провайдеров, платных интеграций, замеров модели или доказанной экономии на реальном туре. Нет полного юридического анализа API-лицензий. Есть достаточная основа, чтобы не начинать с заведомо ложных предпосылок, выбрать A0 и написать согласованные PRD+SSD.


## 7. Что уточнено в 0.2: облако без архитектурной скидки

Официальные описания ChatGPT Projects, веб-поиска и работы с файлами, а также Claude Search/file creation дают основания спроектировать обычный чат как основной host. Наличие функций зависит от аккаунта/настроек; документация не подтверждает конкретный пилот, качество результата или одинаковый набор инструментов у всех. [S46–S50]

Рекомендация: один переносимый стартовый файл, две смысловые выдачи, snapshot на границах и единый редакционный стиль. Native Projects, Skills и подключённые приложения могут помогать, но не требуются для запуска. Отсутствие субагента — последовательный reviewer; отсутствие Git — файл/текст; отсутствие актуальной информации — реальный пробел, не прозрачный технический fallback.

Сравнение «cloud почти как local» пока гипотеза. Его проверяют на одинаковом brief и сопоставимых данных; дополнительные API нельзя ошибочно выдать за интеллект оркестрации. Названия моделей и квоты не закрепляются в переносимом методе, чтобы он не устаревал при смене продуктовой линейки.
