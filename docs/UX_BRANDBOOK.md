# ЕНОТ — брендбук и UX-направление 0.2.0

Оригинальная концепция для этого проекта. Рабочее имя не проверялось на товарные знаки/домен. Образец design-preview.html — визуальная спецификация с синтетическими данными, не реализованное приложение.

## Характер

Умный спокойный друг, который умеет устраивать отдых. Не туристический рекламщик, не оценщик олимпиадных маршрутов, не навязчивый мультипликационный помощник. Тёплый и точный: «этот вариант экономит деньги, но съедает утро» лучше, чем «максимизирует эффективность бюджета».

Luxury = композиция, ясность, забота, уместная деталь. Маленькая игровая награда допустима на фоне взрослого редакционного дизайна. Игровой слой не управляет фактическими статусами.

Вдохновение: подход Pentagram / Impala к выразительным туристическим документам, типографике и навигации. Не заимствовать их логотип, макеты, иллюстрации и проприетарные шрифты; не подписывать «дизайн Pentagram». [S24 в SOURCES.md]

## Токены

| Роль | Значение | Использование |
|---|---|---|
| paper | #F7F3EA | Основной фон |
| ink | #183229 | Основной текст, тёмная карточка |
| muted | #536257 | Вторичный читаемый текст |
| sun | #EBCB63 | Награда, важный акцент; текст ink |
| rust | #99492F | Предупреждение; не один цвет без подписи |
| line | #DCDDD2 | Тонкие разделители |
| white | #FFFFFF | Карточки |

Заголовки: Georgia / Times New Roman / serif. Интерфейс: Segoe UI / system-ui / sans-serif. Цифры tabular-nums. Системные шрифты работают без сети; файлы шрифтов не входят в бандл.

Сетка desktop: до 1180 px полезной ширины, 24 px gap; mobile: поля 20 px, одна колонка. Радиусы 16–24 px, мягкие границы, почти без теней. Ритм отступов кратный 4. Заголовки выразительные, обычный текст 16–18 px. Не уменьшать шрифт ради помещения большой таблицы.

## Четыре поверхности

| Экран | Главное сообщение | Основное действие |
|---|---|---|
| Пожелания | «Как хочется отдохнуть?» | Собрать варианты |
| Исследование | Реальный этап, проверенное, пробелы | Ответить на вопрос / открыть готовое / остановить |
| Выбор | Различия, стоимость, хлопоты, подтверждения | Проработать этот вариант |
| Моя поездка | «Вот план; вот ближайшее действие» | Открыть нужный день / перепроверить перед покупкой |

В приложении/документе наверху название поездки, версия/дата, этап. В облачном чате — краткая строка этапа при смене состояния, не техническая шапка в каждом сообщении. Смена настроек не теряет текст. При уточнении сохраняется контекст и объясняется, что зависит от ответа. Четыре поверхности — смысловая организация, а не обязательные четыре web-экрана.

Никаких ложных статусных анимаций: не показывать «звоним в отель», если используется веб-поиск. Не выдавать внутренние рассуждения модели за прогресс. Показывать реальные завершённые действия и материальные находки.

## Карточка варианта

Небольшой ярлык типа опыта → название → одна фраза «для кого» → весь бюджет и база → дорога/хлопоты → почему стоит рассмотреть → честный компромисс → состояние проверки и дата → одно действие. Ссылки внешнего бронирования явно ведут к поставщику, не выглядят как покупка внутри продукта. В чате — «Напишите номер варианта или что изменить», не псевдокнопка. Подборка содержит до пяти уникальных вариантов суммарно за цикл; guide до выбора не прикладывается.

Технический рейтинг, подробные веса и источники — раскрываемые блоки. Риск, который меняет решение, раскрыт сразу. Для mobile таблицы превращаются в карточки, а не уходят за горизонтальный скролл.

## Награда

«87 енотов из 100» + 2–3 предложения про этот результат. Подпись: «редакционная оценка; не гарантия поездки». Отдельно показывать проверенность. При критичных пробелах награда скрывается. Не ставить 98 каждому клиенту; не понижать релакс за небольшое число активностей.

## Guide

**Три слоя чтения, единые для чата и документа.**

1. **Лёгкая суть за 1–3 минуты:** зачем ехать, полный бюджет/резерв/депозит, что подтверждено, важный компромисс, три ближайших действия. Для shortlist — короткое сравнение; для выбранного — решение и ближайшие шаги. Чтения этого слоя достаточно, чтобы не спрашивать «что дальше?».
2. **Практика по моменту:** до выезда, первый день, дни и переезды, быт/помощь, возврат. В дне «обязательное», «по желанию», «план Б». Свобода не пустота.
3. **Глубина для проверки:** строки бюджета, баллы/веса/чувствительность, сравнение с baseline, источники/даты/scope, findings и исправления. HTML — нативные details и якоря; Markdown — разделы ниже с оглавлением. В чате не рассчитывать на работоспособность HTML/сворачивания.

Существенное ограничение не прячется в третьем слое. Для короткой поездки весь plan может быть компактен; не раздувать документ ради трёх одинаковых разделов. Стиль, голос и иерархия одинаковы во всех режимах; шрифты/цвета интерфейса чужого чата не поддаются нашему управлению.

Встроенная навигация по якорям, короткие карточки «такси», «еда», «помощь», «обратно». Адреса, координаты и телефоны доступны текстом. Ссылки на карту не единственный способ понять, куда идти.

## Доступность и экспорт

Проверять обычный текст на контраст 4.5:1, крупный — 3:1; состояние не выражается одним цветом. Видимый keyboard focus, семантические заголовки, подписи к полям. Уважать reduced-motion. Проверять 390 px и desktop; базовый текст читается без JS.

HTML самодостаточен по тексту и CSS. Внешние карты/цены требуют сети, это подписано. При необходимости print CSS даёт удобную печать; отдельный PDF-движок не вводится до запроса. Реальные фотографии — только с установленными правами/атрибуцией. Сгенерированная картинка не выдаётся за фотографию конкретного жилья или вида из номера.

## Редакционные правила

Не «незабываемая атмосфера», а «два вечера без переездов, баня по записи и прогулка прямо от дома». Не «брони подтверждены», а «предложения проверены в 14:10; покупка ещё не сделана». Не «тур на 40% дешевле рынка», а сопоставимая корзина с датой, источником и расчётом либо отказ от процента.


## Облачный диалог: без технической нагрузки

| Внутреннее событие | Понятное сообщение |
|---|---|
| Нет субагентов / Git | Ничего об этом: выполнить последовательные проверки и сохранить snapshot доступным способом |
| Не подтверждена квота на всех | «Для всей компании размещение пока не подтверждено; этот вариант условный» |
| Поиска актуальных источников нет | «Сейчас доступны идеи, но не проверка цен и мест. Для неё нужен поиск» и одно доступное действие |
| Ход закончился до подборки | «Проверены три варианта; осталось сопоставить дорогу двух других. Напишите „Продолжай подбор“» — только если это реально сделано |
| Файлы не создаются | «План и данные для продолжения — ниже в сообщении»; не притворяться выданным архивом |
| Shortlist готов | «Напишите номер варианта или что изменить»; никакого автоматического PLAN |

Задача — убрать инфраструктурный шум, не скрыть слабое место решения. Нет технических diagnostics в first readout, нет фальшивых % готовности, асинхронной работы, искусственного «вау» за счёт недоказанных скидок. При прямом вопросе о методе отвечать честно.

## Экспорт и пример

Основная поставка: HTML + Поездка.md + Продолжение.md, ZIP при фактическом создании. В чате — лёгкое начало и реальные ссылки. HTML — весь нужный текст без сети; карта/свежая цена требуют сеть. Проверки верстки и чисел заявлять только фактически выполненные.

Обновлённый design-preview.html сохраняет палитру, типографику и композицию v0.1, добавляет лёгкий summary и раскрываемые практические/проверочные слои. Это **галерея этапов**, не пример выдачи полного guide в первом ответе. Все данные синтетические. Новую картинку/логотип ради смены режима не создаём.
