# ЕНОТ — отдых, который продуман

**Пожелания → до пяти убедительных вариантов → ваш выбор → удобная книжка поездки. В обычном облачном чате или с агентом и репозиторием.**

Версия проекта **0.3.0 · 30 сентября 2026**. Протокол чата **0.2.3**. Это не работающий сервис и не доказательство реальных цен. Активная разработка идёт для владельца. Стартовый файл по-прежнему можно отдать другому человеку позже; это не текущий release gate.

## Мне просто спланировать отдых

Возьмите **[ENOT_CHAT_START.md](ENOT_CHAT_START.md)**. Прикрепите его в свой облачный чат с сильной моделью и напишите: «Спланируем отдых по ЕНОТу. Мои пожелания: …». Поиск актуальных источников нужен для проверяемого подбора. Ничего устанавливать, подключать к Git или запускать в консоли не требуется.

Сначала получите **только подборку до пяти вариантов после проверки**, не пять длинных путеводителей. Выберите вариант или уточните пожелания. После выбора — краткая суть поездки, подробности по разделам и итоговый пакет для сохранения. Для визуального ориентира можно дополнительно приложить [design-preview.html](design-preview.html); текстовые правила стиля уже есть в стартовом файле. ZIP не является обязательным входным форматом: один Markdown-файл проще переносить между чатами.

Стартовый файл самодостаточен: для одной поездки не нужны остальные документы этого репозитория. Создавать Project тоже необязательно. Для регулярного использования можно сохранить этот файл как источник в отдельном личном проекте; соседние чаты, личная память и доступ к Git не предполагаются.

## Я развиваю продукт

Начните с [BLUEPRINT.md](BLUEPRINT.md), раздела «Решение в одной странице». Затем [STATE.md](STATE.md) и [плана поставки](docs/DELIVERY_PLAN.md). Дизайн-образец показывает несколько экранов и итоговый документ вместе, но реальный первый проход останавливается на подборке.

**Основной режим — сильная модель в облачном чате.** Локальная оболочка, Git, субагенты, API и MCP — способы ускорить и автоматизировать тот же метод, а не входной билет к качественному результату. Для обычного пользователя устройство процесса скрыто; ограничения конкретных цен, мест и условий всегда видны.

## Стартеры: обычные сообщения, не установленные команды

**Подобрать:** «Спланируем отдых по ЕНОТу: …». Агент собирает нужные условия, исследует и проверяет, показывает до пяти вариантов и ждёт выбора.

**Выбрать:** «Проработай вариант 2». Это разрешает PLAN для выбранного варианта, не бронирование. «Нравится» само по себе не разрешает покупки и при неоднозначности не выбирает вариант.

**Уточнить:** «Уберём ранние выезды, остальное оставим». Меняются зависимые части, прежние ограничения сохраняются; новый цикл подбора имеет максимум пять активных вариантов.

**Продолжить в другом чате:** приложить последний файл «Продолжение.md» и стартовый файл; написать «Продолжи с сохранённого места». Агент не притворяется, что видит старый чат; критичные устаревшие данные перепроверяет.

**Перед покупкой / выездом:** «Перепроверь выбранную поездку перед покупкой». Выход: что изменилось, влияние и действие, а не путеводитель заново.

**Для разработчика:** «Прочитай STATE и docs/atoms/A0_A1/ACCEPTANCE.md. Ближайший gate — чистый облачный пилот по PILOT_PACKET, не новый PRD и не локальный A2». Локальное усиление по-прежнему необязательно. Отсутствие Git, субагентов или Python у путешественника не блокер. Свежие данные и честные ограничения остаются обязательными.

## Что передавать и где хранить

Путешественнику — один стартовый файл, при желании плюс визуальный образец. Разработчику — весь бандл. В постоянные Sources проекта разработки достаточно BLUEPRINT, STATE, DELIVERY_PLAN и CONTRACTS (4); AGENTS — короткая инструкция. Остальное — адресные справочные материалы, не постоянная память.

Метод и будущий код могут жить в Git. Рабочие поездки — в текущем чате и выданных файлах либо локально вне Git. Облачный сеанс не предоставляет доступ к репозиторию владельца. Сохранённый пользователем итоговый пакет — точка переноса, не обещание вечного хранения вложений провайдером. Паспорта, карты, cookies и коды брони исследованию не нужны.

**Выход поездки:** удобный HTML, текстовый «Поездка.md» с источниками и расчётами в глубине, компактное «Продолжение.md». При наличии файлового инструмента — одним ZIP плюс основная ссылка на путеводитель. Без него — те же сведения прямо в чате, без фиктивной ссылки на файл.
